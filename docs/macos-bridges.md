# macOS Bridge Architecture

GFM is macOS-only, but the core codebase still needs narrow platform
boundaries. Native integration should be deep, typed, and explicit rather than
spread across UI, indexing, preview, search, operation, and packaging code.

This document is the contract for macOS bridge ownership.

## Ownership

`crates/mac` is the typed Rust facade over macOS platform behavior. It owns the
high-level bridge contracts and keeps framework details away from product
subsystems.

`crates/mac-sys` owns low-level Objective-C, CoreFoundation, C, and system ABI
bindings. Unsafe calls and foreign ownership rules belong there unless a small
isolated wrapper is clearly safer in `crates/mac`.

Consumers should depend on typed bridge reports, decisions, descriptors, and
commands. They should not call platform APIs directly from search, operations,
indexing, preview, diagnostics, or UI rendering paths.

runtime probing everywhere. Unsupported or unavailable framework calls should
return typed reports with reasons.

## Thread Policy

Every bridge must declare one of three thread policies:

- `main-thread`: must run on the app main thread or through a main-thread
  dispatcher. AppKit window/menu activation and some Quick Look presentation
  work belong here.
- `background-safe`: may run off the main thread, but must still respect
  framework ownership, autorelease, and cancellation rules.
- `dedicated-worker`: runs on a long-lived worker because the API owns a stream,
  run loop, callback lifecycle, or blocking system interaction.

Thread policy is part of the public contract. A caller should be able to decide
whether a bridge can be used from a worker without reading platform glue.

## Framework Boundaries

### AppKit

AppKit ownership stays at the native shell and main-thread presentation
boundary. UI rendering should use GPUI, while AppKit integration covers window
activation, menus, application lifecycle, system appearance, and native sheet or
panel boundaries where Finder parity requires it.

### Foundation

Foundation-backed host profile and filesystem-adjacent data should return typed
Rust structs. Host support decisions must report macOS version, CPU
architecture, memory floor, logical CPU floor, and primary/compatible/unsupported
status with reasons.

### CoreServices And LaunchServices

CoreServices and LaunchServices bridge Finder-visible metadata:

- localized kind strings;
- display-name behavior;
- extension-hidden names;
- package and app bundle classification;
- icon and badge identity;
- bundle identifiers;
- document associations.

Indexing and preview should consume these reports so search, package traversal,
and icons agree with Finder.

### Security

Security bridges own permission readiness, protected-scope decisions, and
security-scoped bookmark create/resolve/start/stop behavior.

The operation engine must receive allow, prompt, or deny decisions before
mutation. Indexing and preview workers must also respect protected-scope policy
so background work does not produce surprise TCC prompts or partial reads.

### FSEvents

File-event streams belong on a dedicated worker. They should emit typed
create/modify/remove/rename/rescan events and surface dropped-event conditions
as repair work instead of treating the index as silently current.

### Spotlight

Spotlight is an auxiliary metadata source, not the primary truth for GFM search.
Spotlight reconciliation may enrich or repair metadata, but machine-wide search
correctness must remain owned by GFM indexes.

### DiskArbitration

Volume integration owns mount, unmount, eject, capacity, APFS/container
metadata, network volume classification, and topology changes. DiskArbitration
callbacks belong on a dedicated worker and should invalidate index, operation,
and sidebar policy through typed volume events.

### FileProvider

FileProvider integration owns iCloud and provider-backed state:

- downloaded versus evicted placeholders;
- materialization confidence and source;
- download/evict command availability;
- provider progress;
- conflict/offline/error state;
- invalidation events.

Preview, thumbnail, indexing, and operations must not treat remote placeholders
as ordinary local files. FileProvider state should gate expensive native preview
or content extraction work before it reaches Quick Look or index workers.

### Quick Look

Quick Look preview and thumbnail requests should enter through preview
scheduling and cache policy. Native presentation work is main-thread-sensitive;
bulk thumbnail work must remain cancellable and priority-aware so it cannot
starve navigation, search, or foreground file operations.

## Error Contract

Bridge errors must be typed and actionable. Avoid returning opaque strings when
the caller needs to distinguish:

- unsupported framework on the current macOS build;
- unavailable API because host tools or entitlements are missing;
- path missing;
- permission denied;
- user prompt required;
- provider offline;
- request timed out;
- cancellation;
- corrupt or inconsistent platform response.

Typed errors let GFM degrade gracefully without guessing whether to retry,
prompt, repair, or fail closed.

## Cancellation

Long bridge calls need checked variants where practical. Cancellation should be
observed before:

- path probes;
- bookmark resolution;
- FileProvider state reads;
- Spotlight metadata reads;
- volume scans;
- event drain loops;
- icon, thumbnail, or preview generation;
- diagnostic report writing.

Cancellation does not mean the platform API can always be interrupted
mid-syscall. It means GFM should stop before starting avoidable work and should
not continue follow-up work after cancellation is visible.

## Privacy

macOS bridges naturally touch personal file paths, metadata, comments, tags,
provider domains, and volume names. Diagnostic exports must remain aggregate or
privacy-reviewed. Bridge diagnostics should prefer stable categories and status
reasons over raw paths unless the user explicitly opts into local debugging.

## Verification

Bridge changes need tests at the boundary they affect:

- pure Rust mapping tests for status decisions;
- host-backed smoke tests where the framework call is available and deterministic;
- cancellation tests for checked variants;
- unavailable-framework and unsupported-path tests;
- permission prompt/deny tests that prove no mutation or expensive work starts;
- diagnostics that expose bridge status without leaking private data;
- app-build tests for main-thread-only presentation surfaces.

Every required bridge should eventually move to implemented only after code,
host validation, and deterministic CI coverage exist. The bridge inventory is
allowed to be blunt; it should never pretend an integration is done before it is.
